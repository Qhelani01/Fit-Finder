# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

---

## 1. A matching query completes all three tools

For a query that has at least one matching listing, FitFindr should complete the full search → outfit suggestion → fit card workflow and populate `selected_item`, `outfit_suggestion`, and `fit_card` in at least 4 of 5 runs.

**Why this target:** 4 of 5 allows one failure because the workflow includes LLM calls that can vary, time out, or encounter API/rate-limit errors. It also accounts for keyword search being sensitive to how the query is phrased.

---

## 2. An impossible query stops before the second tool

For an impossible query that returns no listings, FitFindr should stop after the search and tell the user to change their search criteria in 5 of 5 runs, without calling the outfit or fit-card tools.

**Why this target:** 5 of 5 is appropriate because the empty-result check is deterministic code. If `search_listings()` returns `[]`, the agent should always follow the same stop behavior.

---

## 3. State consistency

In 5 out of 5 test runs, the listing stored in `session["selected_item"]` must have the same unique listing ID, price, and platform as the `new_item` passed to `suggest_outfit()`.

**Why this target:** This target is 5/5 because transferring session state is deterministic code, so the selected item should never change between steps.

---

## 4. Fit card quality

In at least 4 of 5 runs, the fit card must contain 2–4 complete prose sentences and correctly mention the selected listing's title, exact price, and platform. The title may be shortened only if it still clearly identifies the same item. The caption must not state a different price, platform, size, brand, or item type from the selected listing. Emojis and standalone hashtags do not count as sentences.

**Why this target:** 4 of 5 is appropriate because the caption is generated by an LLM, so its wording and formatting can vary between runs. The required listing facts, however, give us objective checks for whether the generated caption is acceptable.

---

## 5. Price filtering

In 5 out of 5 test runs, every listing returned by `search_listings()` must have a price less than or equal to the user's `max_price`. For example, a query with `max_price = $30` must never return a listing costing more than $30.

**Why this target:** This target is 5/5 because price filtering is deterministic logic and should behave consistently on every run.
